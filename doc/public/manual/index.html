节点搭建

节点页装 Xray / sing-box 内核，用模板新建入站——VLESS + Reality + Vision 一类组合保存即下发生效。

中转转发

端口转发开箱即用；隧道转发支持转发链，一跳一跳把流量送到出口节点，负载策略有主备 / 轮询 / 随机三档。

链式代理

链在服务器侧拼：隧道转发链逐跳接力，入站出站按出站配置再拨下一跳，按场景选一种。

导入节点

别处搭好的节点用分享链接或订阅导入面板，照样能对接中转、进自己的订阅。

订阅

订阅详情里看流量统计、复制链接、扫二维码，8 个客户端入口：7 个点名调起对应客户端导入，「通用」只复制订阅链接。

通知与备份

网站配置里开 Telegram / Webhook 通知（10 类事件 + 资源告警），数据可按 13 类导出 / 导入 JSON 备份恢复。

快速上手

从零到发出第一个可用订阅，最短路径是五步：装面板 → 加节点 → 建入站 → （可选）对接中转 → 建订阅导入客户端。下面每一步都给了入口页，细节分别在各专章里逐步配图讲。

登录面板

浏览器打开面板地址，用管理员账号登录即可，没有额外的登录方式。登录页是英文界面：字段是 Username / Password，按钮是 Sign In。实测把浏览器语言改成中文后，登录页仍然是英文——登录页文案是写死的，没有中文版；登录进入面板后，内页是中文。这不是故障，不用改设置。本手册不放登录页截图，记住这一点即可。

五步走完一条链路

  1. 安装面板在一台服务器上装好面板，浏览器打开面板地址，用默认管理员账号登录后立即修改密码。安装命令是演示写法，见 安装部署。
  2. 添加节点先在 网站配置 里确认面板后端地址，再到节点页新建节点，把生成的安装命令拿到目标服务器上执行，等节点状态变为在线。见 搭建节点。
  3. 新建入站在节点上安装 Xray 或 sing-box 内核，再新建入站（例如 VLESS + Reality + Vision），点「创建并下发」后入站即出现在落地列表里。见 新建入站。
  4. 对接中转（可选）流量不想从落地机直出时，到中转页建隧道：只换入口用端口转发，要多跳链路用隧道转发。见 对接中转。
  5. 建订阅并导入客户端到订阅页新建订阅，在订阅详情里复制链接或选客户端一键导入。见 订阅设置 与 导入到客户端。
实测提醒：节点地址别填 127.0.0.1

历史版本实测（当前版尚待复核）：节点地址填 127.0.0.1 时，订阅显示 0 个节点，并提示“该订阅当前没有可用节点”；把节点 IPv4 改成公网 IP后，订阅才有节点（域名填独立的“域名 / 主机名”字段，别填进 IPv4 字段）。订阅卡片上的节点数就是这个订阅当前可用的节点数，看不到节点先查这里。详见 订阅设置 · 订阅显示 0 个节点。

首次登录清单

  • 修改管理员初始密码，设置为强密码并妥善保存
  • 确认面板地址（IP / 域名 + 端口）能从外网打开
  • 在网站配置里核对“面板后端地址”，节点靠它回连面板
  • 节点地址填公网 IP 或域名，不要填 127.0.0.1（原因见上方实测提醒）
  • 记下面板版本，后续升级与排障都要对版本（本手册文字对应 2.1.34）
复制按钮没反应？

浏览器只在 HTTPS（或 localhost）页面里完整开放剪贴板。面板走公网使用时，建议配好域名与 HTTPS 再分发订阅链接。

安装部署

OVO 分两端：面板端管用户、节点、隧道与订阅；节点端（agent）装在每台中转机 / 落地机上，负责实际转发和运行内核。

安装 OVO 2.1.34

下面使用公开的定版 Release 资产，并校验 SHA-256。节点地址与参数以实际部署为准。

面板端

环境要求

  • 操作系统：Linux（推荐 Debian 10+ / Ubuntu 20.04+）
  • 已安装 Docker 与 Docker Compose
  • 放行前端端口 6366 与后端端口 6365（或你自定义的端口）

安装 OVO 2.1.34

# 公开定版资产；校验成功后执行
curl -fsSL https://github.com/yhfc1775-maker/ovo/releases/download/2.1.34/panel_install.sh -o panel_install.sh && curl -fsSL https://github.com/yhfc1775-maker/ovo/releases/download/2.1.34/panel_install.sh.sha256 -o panel_install.sh.sha256 && sha256sum -c panel_install.sh.sha256 && bash panel_install.sh

按脚本提示选择安装面板，过程中会让你确认：

  • 前端端口：默认 6366，浏览器访问面板用它；
  • 后端端口：默认 6365，节点 agent 回连面板用它。

访问面板

安装完成后访问 http://服务器IP:6366。默认管理员账号是 admin@user；初始密码是随机生成的（安装时也可以用 OVO_ADMIN_PASSWORD 环境变量指定），安装输出里会明文给出一次，并写进容器内一次性文件 /app/data/initial-admin-password.txt。登录页是英文界面（Username / Password / Sign In），不随浏览器语言变化、没有中文版，属正常现象；面板内页为中文。

警告

首次登录后请立即修改初始密码。初始密码只在安装输出和一次性文件里出现一次，面板又直接管着所有节点，不要裸奔。已有数据库升级不会重播口令。

节点端

节点端不在这里单独下载脚本——安装命令由面板生成：在面板里新建节点后，命令里已经带好面板地址与该节点的密钥，复制到目标服务器执行即可。命令的占位写法是：

# 演示指令（示例）：实际命令请在面板「节点 → 新建节点」里生成后复制
./install.sh -a "http://面板地址:6365" -s "节点密钥"
  • -a：面板后端地址，节点用它回连面板，所以网站配置里的面板后端地址要先填对；
  • -s：这个节点的密钥，在新建节点时生成；之后随时可以在节点详情里点安装命令再看，不用怕丢。
部署注意：一台宿主机只装一个 agent

同一台宿主机上并行跑多个 agent 会共享宿主的 nftables 命名空间、互相干扰白名单规则。多节点请分开宿主机，一台机器一个 agent。

面板与节点同机时

如果面板机同时也是节点机，agent 回连面板走本机地址即可；但节点的对外地址（给订阅用的 IPv4）必须填公网 IP 或域名——填 127.0.0.1 会让订阅显示 0 个节点，见 快速上手 的实测提醒。

反向代理（可选）

想用域名 + HTTPS 访问面板时，在面板前面加一层反向代理，把域名转发到前端端口 6366，后端地址同步改成代理后的地址。配好 HTTPS 后，面板里的复制按钮、订阅链接分享都会更顺畅。订阅链接要单独经前置地址对外时，见 订阅前置地址。

升级

面板和节点分开升级：面板在网站配置里自升级，节点在节点详情里升级 / 回退。升级前先去 网站配置 · 数据备份与恢复 导一份 JSON 备份，出问题能整表恢复。

面板自升级（网站配置）

测试面板上的实测状态：当前版本 2.1.23、最新版本 拍摄时的更新版本、状态“可升级”；部署目录 /opt/ovo-panel，后端容器 ovo-panel-backend。你自己的面板以网站配置里显示的为准。

  1. 先备份网站配置 → 数据备份与恢复 → 选择并导出，勾选需要的类型（拿不准就全选 13 类）。
  2. 检查更新在网站配置的面板升级区点检查更新，确认检测到的最新版本号（如 拍摄时的更新版本）。
  3. 确认升级点立即升级后会弹出确认框：本次将升级到最新版；升级过程要访问 Docker Socket，并会在短时间内中断当前面板服务；确认 Docker Socket 可用且挂载权限正常、当前面板允许暂时停止和重启、已选择正确的更新通道与目标版本，再点确认升级。
  4. 等面板回来升级完成后面板自动重启，刷新页面重新登录，侧边栏左下角的版本号应已变为新版本。
  5. 升级后核对看概览：节点在线数、订阅数量与升级前一致；随便打开一个订阅详情确认节点数正常。
升级未落地有通知

在网站配置的通知里开启“节点升级未落地”事件后，升级下发后 5 分钟未回连目标版本会提醒一次，不用守在面板前等。见 网站配置 · 通知。

脚本升级（演示）

也可以重新运行安装脚本走升级菜单（演示写法，换成你自己的实际脚本地址）：

# 演示指令（示例）
./panel_install.sh
# 在菜单中选择「更新面板」

节点 agent 升级与回退

  • 单个节点：打开节点详情，点升级；升级后看详情里的版本号与“已运行”时长确认新版本已起来。
  • 升级后异常：同一位置点回退，退回上一版本，再排查原因。
  • 节点长期离线先别急着升级：先确认机器本身和 agent 进程是否还活着，见 常见问题。

搭建节点

“节点”是装了 agent 的服务器。把机器加进面板、装上内核，它就能承载入站（落地）或担任中转入口 / 中间跳。本章走完新建节点 → 执行安装命令 → 装内核，入站的创建在下一章 新建入站。

新建节点：完整步骤

  1. 先确认面板后端地址去 网站配置 确认后端地址是节点机器能访问到的地址——生成的安装命令会把这个地址带进去，填错了节点永远连不上。
  2. 打开新建节点节点页右上角点新建节点，弹出下面的表单。表单字段不少，逐项说明见下一节。
  3. 填名称与地址节点名称可自定义、之后可改名；地址填这台机器的公网 IPv4 或域名。面板在表单里原话提醒：“节点ip地址是你要添加的入口/出口的ip地址，不是面板的ip地址”。
  4. 复制安装命令保存后复制面板生成的安装命令，形如 ./install.sh -a "http://面板地址:6365" -s "节点密钥"（演示写法）。命令丢了不用慌，节点详情里的安装命令按钮随时能再看。
  5. 到目标服务器执行SSH 登录那台机器，粘贴执行安装命令，等 agent 装好并回连面板。
  6. 确认在线回到节点列表，状态变为在线即成功；长时间离线先查后端地址、6365 端口放行与机器网络。

字段怎么填

安装内核

节点在线后还要装内核，入站才能跑起来。节点页有节点 / 内核两个标签：内核标签里显示 Xray 与 sing-box 的运行状态，在对应节点上选择安装哪个内核（一个节点可以两个都装，按入站需要选）。

新建入站

入站是节点对外提供服务的入口：选一个节点 + 内核，定协议、传输与安全组合，点「创建并下发」后客户端就能连。本章用实测建出的 演示-VLESS（VLESS + TCP + Reality + Vision，端口 52668，节点 r5-node-0241）为例，一步一步走完。

创建步骤

  1. 打开新建入站落地页右上角点新建入站。弹窗顶部写明：留空的 UUID、密码、密钥会自动生成，端口留空则随机分配。
  2. 选模板弹窗上半部是现成模板：VLESS + Reality + Vision（推荐：无需域名和证书，抗探测）、VLESS + XHTTP + Reality、Shadowsocks 2022、Trojan + TLS（自签）、VMess + WS + TLS 等。示例选第一个。
  3. 填名称与端口名称填 演示-VLESS（模板已自动带出「VLESS + Reality + Vision」前缀，名称栏实际为「VLESS + Reality + Vision演示-VLESS」）；端口可以留空随机（从 [20000,60000) 里取），也可以自己指定（只检查是否与已有端口冲突，并放行防火墙）。
  4. 按需展开高级设置模板只定大方向，协议 / 传输 / 安全等字段都在高级设置里，展开可查看或修改，逐项见下节；普通直连场景可以先全部留默认。
  5. 点「创建并下发」面板把配置下发到节点内核，成功后回到落地列表核对。
  6. 回列表核对新入站应出现在列表里：名称、协议组合、端口、所属节点、启用开关都对上，再去 订阅 里看它是否已被订阅收录。

高级设置逐项说明

展开高级设置后，字段分三段：协议与凭据、网络与超时、中转相关。先看协议段的要点：

协议 / 传输 / 安全模板套用的组合在这里落成具体字段，可手动改（如 VLESS / TCP / Reality）。
UUIDVLESS / VMess 的用户凭据，留空自动生成。

VLESS 加密（ENC）VLESS 的加密选项，按客户端支持情况选；不确定就保持模板默认。
Reality 伪装域名Reality 借用的目标站点，默认 www.amd.com；要换成你实际可达、支持 TLS 的站点。

实测坑：最低客户端版本别改高

把最低客户端版本抬到 Xray 新版默认的 26.3.27 后，Clash / Mihomo 客户端会直接连不上这个入站。保持 1.0.0 最稳妥。

字段说明
监听地址默认 ::（监听所有地址）。高级设置里的面板说明：填 127.0.0.1 为仅本机，配合隧道中转用。

导入节点

节点不一定非要在面板里从零搭：别处已经搭好的节点，可以用分享链接或订阅导入面板。导入后它和自建节点一样能对接中转、被订阅收录，区别只是机器本身不受面板 agent 管理。

导入步骤

  1. 打开导入在落地 / 节点相关页面点导入节点。
  2. 粘贴内容把节点的分享链接，或包含节点的订阅地址粘贴进弹窗。
  3. 确认导入结果解析出的节点会出现在列表里，逐个核对名称、地址与端口。

两个口径先记清

① 导入节点的流量不计入订阅统计（订阅计量口径见 订阅设置 · 流量计量口径）；② 网站配置的通知里有一类事件就叫“导入节点连不上”：连续两次检测连不上（约 6 分钟）时推 Telegram / Webhook，恢复时也会通知。导入节点不受面板管控，机器挂了只能去源头处理，面板侧能做的就是及时告诉你。

对接中转

中转 = 让流量先到一台入口机，再送到落地机出去。中转页有四个标签：线路、隧道、规则、质量。本章先看线路与隧道全貌，再分步讲隧道怎么建——分清端口转发与隧道转发是关键，链式代理（多跳）只在隧道转发里有。

两种转发，先选对

端口转发隧道转发
链路入口直达出口，无中间跳可加多跳转发链，再到出口
创建后卡片显示1 入口 0 跳 1 出口跳数随转发链里加的跳数变化
转发链配置没有只有选隧道转发才出现：添加一跳、出口配置
适合单机中转、简单换入口多跳链路、链式代理

创建端口转发：分步

  1. 新增隧道，选端口转发中转页 → 隧道标签 → 右上角新增，弹窗里「隧道类型」选端口转发。
  2. 选转发引擎默认面板转发（默认，功能最全）：节点 agent 直接转发，支持限速和连接数限制，流量按隧道计费模式计入用户配额。
  3. 填入口配置选入口节点（示例为 r5-node-0241）。入口监听端口从节点可用端口范围里分配。
  4. 按需展开高级设置高级设置里有流量计算方式、流量倍率、入口 IP、质量检测目标——倍率决定这条隧道按多少倍计流量，质量检测目标给 隧道质量 页测延迟 / 丢包用。
  5. 点创建，回隧道页核对卡片应显示 1 入口 0 跳 1 出口、状态启用、倍率与流量计算方式无误（结果见上方隧道页截图）。
  6. 去线路页确认走向线路标签里应能看到这条中转挂在对应落地下，入口地址与延迟正常（见本页第一张图）。

隧道转发与转发链：分步

  1. 新增隧道，类型选隧道转发只有这时弹窗里才会出现转发链配置区（端口转发没有）。
  2. 填入口配置选入口节点（可多选）。
  3. 点「添加一跳」逐跳加每一跳（第 1 跳、第 2 跳……）要选节点（可多选）、协议（TLS）、负载策略、连接 IP，字段含义见下节。
  4. 填出口配置出口配置在同一弹窗的下方，继续向下滚动就能看到：出口节点必选（可多选），同样有协议、负载策略与连接 IP；不选出口点创建会被直接拒绝，见下方硬性要求。
  5. 点创建创建前先把硬性要求过一遍（见下方红色提示），不满足会被后端直接拒绝。
链式隧道的硬性要求（实测后端原话）

① 入口、每一跳、出口节点必须全部在线，链路里有离线节点，创建会被拒绝并报“部分节点不在线”；② 同一节点不能在链路中重复出现，重复会报“节点重复”；③ 出口节点必选，出口为空会报“出口不能为空”。另外，负载策略后端只认 fifo / round / rand 三个值。建链前先去节点页确认全链在线、出口已选。

负载策略：三档与概率

每一跳和出口配置里都有负载策略：当一跳（或出口）选了多个节点时，新连接按哪种方式分。策略只有三档，区别全在概率上：

策略后端值怎么分每个出口被选中的概率
主备fifo流量全部走主出口，主出口坏了才切到备用主出口 ≈ 100%；备用平时是 0，只在主故障时接管
轮询roundN 个出口按顺序轮流接新连接：1、2、3、1、2、3……每个约 1/N，长期看最均匀
随机rand每个新连接随机挑一个出口每个约 1/N，但短期分布不均匀，可能连着几次都是同一个
连接 IP 不是第四档策略

第 1 跳字段里的连接 IP 是独立字段：它指定拨到下一节点时用的目标地址（优先用你填的值），不是这一跳从哪个 IP 连出去、不绑定拨号源 IP。多节点跳或多出口时禁用自定义连接 IP，用各节点默认 IP。它和负载策略并列出现，但不是一种分流策略，别混。

  • 想要确定性（平时只走一条线、坏了自动切）：选主备。规则列表里显示的“主备”就是这一档。
  • 想要均摊流量：选轮询；出口数 N 越大，每台分到的越接近 1/N。
  • 随机适合不想让连接顺序可预测的场景，接受短期不均。

示例链路（用户个例，不是通用标准）

一条实测在用的链路：腾讯广州 → 深圳 IX → 美国机器 → SOCKS5 出口。美国机器上用 sing-box / xray 以 SS2022 作入站、再链式拨向 SOCKS5 出口，整条链按隧道转发逐跳配置。注意两点：① 这是用户个例，你的链路按自己的机器情况拼；② 这条链是链式隧道，必须用 agent 模式节点——nftables 节点只支持直连（单入口）隧道，进不了链。整链的 UDP 也是经隧道封装送达出口再发出的，不会因为多跳就丢。

链越长，越要盯质量

每一跳都叠加延迟，某一跳抖动整条链都受影响。建好链后去 隧道质量 看每段的延迟 / 丢包，通知里也可以开“延迟 / 丢包异常”和“回程线路变化”两类事件。

隧道质量

中转页的质量标签，专门看每条隧道的延迟与丢包。链路通不通看隧道列表，跑得好不好看这里——注意这一页看的是带数据的隧道卡片，不是空标签页。

探测是怎么跑的

  • 每秒探测一次：质量页默认每 1 秒对每条隧道探测一轮，页头会显示最近更新时间；
  • 间隔可改：探测间隔在 网站配置 · 基本设置 里调整，范围 1–3600 秒，默认 1 秒。隧道多、机器弱时可以调大，别让探测本身成为负担；
  • 测什么：分两段——入口→出口看隧道内部这一段，出口→测试目标看落地机到外网的质量。两段分开，哪段出问题一眼定位。

质量检测目标从哪来

“出口→测试目标”测的目标，是建隧道时在高级设置里填的“质量检测目标”（见 对接中转 · 创建端口转发），图中示例是 www.bing.com:443。Host 与 Port 都留空时默认测 www.bing.com:443，不用补填；只填一半或填了无效值才需要回隧道编辑里处理。

怎么用这一页

  • 选隧道看分段数：延迟突然抬升、丢包出现，先看是入口→出口段还是出口→外网段的问题；
  • 链式链路逐段排查：多跳链路整链慢时，结合每一跳节点的 节点详情 监控逐段缩小范围；
  • 开异常通知：网站配置的通知里有“延迟 / 丢包异常”（连续 3 次检测、约 9 分钟，丢包 ≥20% 或延迟超阈值触发）和“回程线路变化”两类事件，质量恶化会主动推给你，不用天天盯页面。见 网站配置 · 通知。

规则

中转页的规则标签，管理转发规则：一条规则 = 在某条隧道上，把某个入口端口的流量送到一个落地地址。先说清一个容易搞混的点：地址栏的 /forward 打开的就是这一页（中转 - 规则），和 /tunnel 对应中转 - 隧道一样，都是同一页的两个地址，不是两个功能。

新建规则：表单逐项

  1. 新增规则规则页右上角点新增（页面还提供导入 / 导出）。
  2. 填规则名称自定义，好认即可（如“演示-规则”）。
  3. 选择隧道规则必须挂在一条已建好的隧道上（示例挂在演示-端口转发下），隧道决定入口侧的走向。
  4. 入口端口留空自动分配（从入口节点可用端口里取）；有明确规划时才手填。
  5. 监听 IP一般留空（监听全部）；只想在某个 IP 上接流量时才指定。
  6. 落地地址格式 IP:端口 或 域名:端口，支持多行——一行一个目标，多个目标时按隧道 / 规则的负载策略分流。
  7. 保存后回列表核对新规则应出现在对应隧道分组下，状态正常、入口 / 目标无误。

规则列表字段怎么看

字段含义
策略（主备）多个落地目标时的分流方式，就是 对接中转 · 负载策略 三档之一：图中两条都是主备（fifo）——流量全走主目标，主目标坏了才切备用，备用平时被选中的概率是 0。另两档是轮询（round，各约 1/N）与随机（rand，各约 1/N、短期不均）。
入口 / 目标入口 = 客户端连的地址（入口节点 IP:入口端口）；目标 = 流量最终送到的落地地址。
总流量这条规则累计跑过的流量；排查“没在用却耗流量”先看它。
编辑 / 诊断 / 清零 / 删除编辑改配置；诊断测这条规则通不通；清零把总流量计数清零；删除移除规则。

规则和什么有关

  • 和用户额度有关：每个用户有“规则数量”上限（新建用户默认 10），用户能建的转发规则不超过这个数，见 用户管理；
  • 和隧道有关：规则挂在具体隧道上生效，隧道删了 / 停用了，对应规则也就不通了；
  • 和限速有关：限速规则是独立的一类数据，备份导出时单独成项（见 网站配置 · 数据备份与恢复 的 13 类数据）。
规则不生效先查三处

隧道是否启用 → 用户规则数量是否已用满 → 目标节点是否在线。三处都没问题，用规则卡上的诊断测一遍，再看 隧道质量。

订阅设置

订阅是把节点打包成一个链接交给客户端的东西：节点建好后建订阅，在订阅详情里复制链接或一键导入客户端。本章走新建订阅 → 看懂列表与详情 → 流量计量口径 → 处理“0 个节点”。

先说清：卡片上的“节点数”是什么

订阅卡片与详情标题下的节点数，是这个订阅当前可用的节点数——入站建好、中转就绪、分享地址有效时才计数。它不是“你建过几个节点”，而是“这个订阅现在真正能用的有几个”。显示 0 的排查见本页下方专节。

新建订阅：分步与表单逐项

  1. 新建订阅页右上角点新建订阅，弹出下面的表单（上半部先填基本项）。
  2. 填基本项名称、到期日期、流量上限、每月重置——逐项见下表。
  3. 选范围落地范围（全部落地 / 指定落地）、中转范围、订阅模板。
  4. 先预览再保存点预览（看看结果）确认这个订阅实际会包含哪些节点，没问题再保存。
  5. 回列表核对新订阅出现在列表里，节点数 ≥1、流量 0 B 起步；节点数不对先看“0 个节点”一节。
字段怎么填
名称自定义（如“我的手机 / 小明”）。表单注明：订阅有独立的 UUID / 密码。停用、到期或流量用完后，独立凭据会从节点上删除、已导入的配置连不上；但共用凭据（SS、导入节点）的已导入配置仍能连，要断开须改对应入站的密码；下发失败时还会留下待同步状态，不保证立刻全部断开。
到期日期可点 30 天 / 90 天 / 1 年快捷填充，也可以自己选日期；留空 = 永不过期。

订阅显示 0 个节点（实测）

最常见原因：节点地址填了 127.0.0.1

历史版本实测（当前版尚待复核）：节点地址是 127.0.0.1 时，订阅显示 0 个节点并出现上面的红字提示；把节点 IPv4 改成公网 IP后，订阅立刻有节点（域名填独立的“域名 / 主机名”字段，别填进 IPv4 字段；测试面板上改完即恢复）——不用重建订阅。测试面板的节点详情里 IP 正是 127.0.0.1，就是这个状态的来源，见 节点详情 那张图。

流量计量口径

订阅详情里有一段面板原文说明“已用”怎么算，归纳如下：

  • 独立凭据协议按订阅计量：VLESS / VMess / Trojan / Hysteria2 / TUIC 等每个订阅有独立 UUID / 密码的协议，流量天然能归到订阅头上；
  • Shadowsocks 要开原地多用户：SS（2022 与传统方法均可）需在入站开启「原地多用户」后才按订阅计量；未开启的 SS 入站不计入。另有几类 SS 入站同样不计入：ShadowTLS 前置、仅中转、带链式出口、已配置分流、开启 PROXY 协议的入站；以上几类限制只适用于 SS 原地计量，非 SS 的独立凭据协议按订阅计量；SS 原地多用户还须下发成功才计量；
  • 导入节点不计入：导入的外部节点流量不算进订阅（见 导入节点）；
  • 周期口径：订阅「已用」从本周期开始（订阅创建或上次重置流量时）累计，只统计上次重置之后的新流量；详情里选时间范围查看时，合计的是所选范围内、本周期内的流量，范围完全覆盖本周期时与「已用」相等。

订阅分配

订阅建好后还要分配给用户，对方才能在自己名下使用。入口就在订阅页顶部的订阅分配标签（与订阅管理并列）。分配关系也是备份数据里独立的一类（“订阅分配”，见 网站配置 · 数据备份与恢复）。

分配要点

  • 先有用户、再有订阅，最后做分配——顺序反了找不到目标；
  • 一个订阅可以分配给多个用户共用，也可以给不同用户分配不同订阅做隔离；
  • 分配只决定这个订阅在该用户名下是否可见；用户自身的流量额度、过期时间、停用状态等见 用户管理，但它们约束的是面板内的用户配额，不约束已经发出去的裸 token 订阅链接；
  • 要收回使用权时，取消分配只收回面板内可见性，已经复制出去的订阅链接不会失效；必须用订阅详情里的重置链接和凭据（或删除订阅）才能让已发链接失效。

订阅前置地址

订阅链接默认按面板地址生成。如果你的订阅要经一层前置地址对外提供（例如订阅入口挂在 Cloudflare 后面、与面板本体不在同一地址），就需要在网站配置里把订阅前置地址配好，让订阅链接按前置地址生成，客户端拿到手的才是能直连的地址。

什么时候需要配

  • 面板用域名 + HTTPS 对外，但订阅链接里还是 IP / 内网地址；
  • 订阅入口经过 CDN 或反代，与面板管理地址不同；
  • 客户端导入后节点地址连不上，但面板里看节点一切正常——典型的地址生成不对。

配置步骤

  1. 准备前置域名前置域名必须是一级子域名（如 sub.example.com），不要用多级子域名。
  2. 先灰云接入把域名解析先设为灰云（仅 DNS），等证书签发完成，确认 HTTPS 能正常打开后，再改橙云开代理——顺序反了容易卡在证书签发。
  3. 加缓存绕过规则在 Cloudflare 里建一条 Cache Rules：匹配 URI 路径 /api/v1/open_api/sub/*，动作选绕过缓存。订阅内容是动态的，被 CDN 缓存住的话，用户更新订阅拿到的还是旧节点。
  4. 在网站配置里填前置地址把对外提供订阅的那个地址填进订阅前置地址，不要填内网地址。
  5. 在订阅管理里选链接地址网站配置里保存的只是备用地址列表，订阅详情的链接地址默认仍是面板地址；须在订阅管理页的“链接地址”选择器里选相应前置，再复制链接。地址要含协议、可带端口、不带路径。
  6. 自检用下面的命令看响应头，cf-cache-status 应为 DYNAMIC（或 BYPASS）；确认链接里的地址已是前置地址，再导入客户端实测。注意：DYNAMIC 单独不能证明 Bypass 规则命中，看到 HIT / MISS 说明请求被缓存、规则未生效。
# 自检（演示写法）：把域名与订阅路径换成你自己的
curl -sI "https://sub.example.com/api/v1/open_api/sub/你的订阅标识" | grep -i cf-cache-status
# 期望输出：cf-cache-status: DYNAMIC（或 BYPASS）
和“节点地址填 127.0.0.1”是两类问题

前置地址解决的是订阅链接的地址；节点地址填错解决的是订阅里有没有节点（0 个节点）。两个都正常，订阅才真正可用。0 个节点的排查见 订阅设置 · 订阅显示 0 个节点。

常见问题

面板与安装

安装命令从哪来？如何校验定版资产？

面板脚本与节点命令都以你自己的实际部署为准：面板安装使用本页的公开定版 Release 资产与 SHA-256 校验；节点安装命令由面板生成（新建节点后复制，或在节点详情点“安装命令”再看），形如 ./install.sh -a "http://面板地址:6365" -s "节点密钥"。节点连接地址与密钥参数由面板生成。

节点一直离线怎么办？

按顺序查：① 网站配置里的面板后端地址是不是节点机器能访问的地址；② 后端端口 6365 是否放行；③ 目标机器上 agent 是否装好、进程是否在跑（重装就用节点详情里的安装命令）；④ 机器本身网络是否正常。四项都正常再看 节点详情 的连接日志。节点列表里离线节点长什么样，见 搭建节点 的列表截图（地址后显示「未知」）。

复制按钮 / 复制链接没反应？

浏览器只在 HTTPS 或 localhost 页面开放完整剪贴板能力。给面板配域名 + HTTPS 后重试，或在客户端里手动粘贴订阅链接添加。

登录页是英文的，是不是装错了？

不是。登录页只有英文版：字段是 Username / Password、按钮是 Sign In，文案写死在源码里；实测把浏览器语言改成中文后仍是英文，没有中文版。登录进入面板后内页是中文，与安装无关。

这本手册的深色模式刷新后为什么变回去了？

手册右上角的太阳 / 月亮图标可以手动切换深 / 浅色，但切换只在当前打开期间有效，不做保存：刷新页面或重新打开手册后，显示会重新跟随你设备 / 浏览器的系统深浅色设置。想长期用深色，把系统外观设为深色即可，手册会自动跟随。

节点与入站

入站建好但订阅里没有？

先看订阅列表的节点数，再打开订阅详情看提示。若提示“该订阅当前没有可用节点”，最常见是节点地址填了 127.0.0.1——改成公网 IP / 域名立刻恢复（实测）。其余按入站是否启用、中转是否就绪、分享地址是否有效逐项查，见 订阅设置。

Clash / Mihomo 连不上新建的 VLESS 入站？

先查入站高级设置里的最低客户端版本：被改成 Xray 新版默认的 26.3.27 时 Clash / Mihomo 会连不上，改回 1.0.0。见 新建入站 · 高级设置。

“仅允许中转机访问”开了没效果？

这一项靠 nftables 落地：先到节点详情确认 nftables 状态（如 nftables: installed）。不是 nftables 模式的节点不要开它。另外 nftables 节点只支持直连隧道，链式隧道要用 agent 模式节点。

监控页在哪？打开 /monitor 跳回了节点页

这是当前版本的正常行为：管理员没有独立监控页，/monitor 会跳回节点页。看监控用节点卡片实时统计（见 节点详情与监控）加 中转 · 隧道质量页。

中转与订阅

建隧道时找不到转发链配置？

转发链只有选“隧道转发”才出现；选了端口转发就只有入口 / 出口，没有“添加一跳”。要多跳链路，删掉重建为隧道转发，见 对接中转。

建链被拒绝，报“部分节点不在线”、“节点重复”或“出口不能为空”？

这是链式隧道的硬性要求：入口、每一跳、出口节点必须全部在线，有一个离线就报“部分节点不在线”；同一节点在链路里出现两次就报“节点重复”；出口没选就报“出口不能为空”。先去节点页把全链节点确认在线、去重、出口选好，再重建。

负载策略选主备、轮询还是随机？

三档的区别是概率：主备（fifo）流量全走主出口，备用平时被选中的概率是 0，只在主故障时接管；轮询（round）N 个出口按顺序轮流，每个约分到 1/N；随机（rand）每个新连接随机挑，每个约 1/N，但短期分布不均匀。要确定性选主备，要均摊选轮询。详见 对接中转 · 负载策略。

质量页里“入口→出口”显示 — 是坏了吗？

不一定。入口与出口同机、或该段暂无独立探测样本时就会显示 —；重点看出口→测试目标那段有没有数值（如 www.bing.com:443 的 2 ms）。整条隧道都没数，先回隧道高级设置确认填了质量检测目标。见 隧道质量。

/forward 和 /tunnel 是什么？和中转页什么关系？

同一页的两个地址：/forward = 中转 - 规则，/tunnel = 中转 - 隧道。不是独立功能，别重复配置。

订阅前置地址和隧道转发链有什么区别？

订阅前置地址只是订阅 HTTP 拉取地址的选择，不拼链——客户端拿到订阅后直接连节点。隧道转发链 / 入站出站在服务器侧拼链，客户端无感。对比表见 对接中转 · 链式代理。

订阅链接泄露了怎么办？

打开订阅详情，点重置链接和凭据，旧链接立即失效；然后把新链接重新分发，并核对 订阅分配 是否有人不该在名单里。

订阅流量对不上，Shadowsocks 没计入？

先看计量口径：独立凭据协议（VLESS / VMess / Trojan / Hysteria2 / TUIC 等）按订阅计量；Shadowsocks 需在入站开启「原地多用户」才计入；SS 原地多用户还须下发成功才计量。ShadowTLS 前置、仅中转、带链式出口、已配置分流、开启 PROXY 协议的 SS 入站与导入节点都不计入——以上几类限制只适用于 SS 原地计量，非 SS 的独立凭据协议不受影响。见 订阅设置 · 流量计量口径。

数据怎么备份？还有 Gist 备份 / PostgreSQL 吗？

当前版本的数据备份在网站配置 → 数据备份与恢复：导出 / 导入 JSON，共 13 类数据，见 网站配置。PostgreSQL 的当前部署与迁移说明见项目文档；历史截图只作为操作位置参考。
